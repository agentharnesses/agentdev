Follow-up to `2026-08-21-0855-sort-mst-replaces-the-ad-hoc-adaptive-pairing.md`, same session. User asked to confirm two properties and, mid-sentence, questioned the design itself: "individual questions should be compared in isolation... there's no point in comparing two results from the same method... I wonder if it's really pure elo."

First property was already correct: `elo_cmd` already builds a separate pool and runs a separate tournament per `step.id` — no cross-question comparison was ever possible, confirmed by re-reading the loop rather than assumed.

Second was a real bug, not just a design nitpick. Quality's competitors were `(variant, repeat_index)` pairs — e.g. 9 competitors for 3 variants × 3 repeats — so Sort-MST could and would pair two of one variant's own answers against each other. Worse than merely wasteful: Sort-MST prefers close-rated pairs, and a variant's own repeats tend to cluster at a similar rating (same method, similar quality), so as ratings settled the tournament would drift *toward* same-variant comparisons over time, not away from them. And a same-variant comparison answers a question `run_consistency_elo` already exists to answer ("does this method agree with itself") — the two-tournament split was supposed to keep "which approach is better" and "does this approach repeat itself" separate, and the flat individual-answer pool quietly re-merged them.

The "is this really pure Elo" question sharpened the fix. Standard Elo never compares an entity to itself — not because of a special rule, but because the competitors *are* the things being ranked, so self-play is never a state the formalism can reach. The bug came from making competitors `(variant, repeat)` tuples instead of variants — which manufactured a same-method-comparison possibility plain Elo was never designed to have. Fix: competitors are variants, full stop, in both tournaments now (quality already matched this for consistency, just not for quality). `run_quality_elo`'s payload changed from `dict[str, str]` (one fixed answer per competitor) to `dict[str, list[str]]` (every repeat answer for that variant), with each judged comparison drawing one fresh random answer from each side — so a same-variant comparison is now structurally impossible (Sort-MST only ever produces edges between two distinct competitors, and there are only as many competitors as variants), and a pair Sort-MST revisits across rounds (still intended, per the entry above) compares a genuinely different pair of texts each time instead of restating the same two answers or, worse, comparing a variant to itself.

`_run_tournament`'s `judge_fn` signature grew a third `rng` argument so quality's per-comparison sampling shares the tournament's one RNG stream rather than needing a second seeded instance. 4 new/rewritten tests, including one that directly encodes the fix (`test_run_quality_elo_never_pits_a_competitors_own_answers_against_each_other`) and one confirming the fresh-sampling mechanism actually varies text across repeated comparisons of the same pair. 122/122 suite passes. `cli.py`'s `elo_cmd` simplified as a side effect — quality and consistency now share one `answers_by_variant` collection per step instead of building two differently-shaped pools.
