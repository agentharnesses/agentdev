Follow-up to the embedding-consistency entry above, same session. User's hypothesis: "if an agent is looking at different files across different turns, then the model might be guided into different actions" — should file-touch consistency across a variant's own repeat runs be tracked too.

Much cheaper to try than the embedding idea, and it showed: `metrics.py` already extracts `distinct_files_touched` from every transcript this project has ever produced, so this needed no new dependency, no model download, no network access — just comparing a set the code was already computing, across a variant's own repeats, on the same per-step granularity `run_quality_elo`/`run_consistency_elo` already use. Built `file_consistency.py` (`jaccard_similarity`, `mean_pairwise_jaccard`, `file_consistency_scores` — structurally identical to `embeddings.py`'s cosine-similarity analogs, just Jaccard over sets instead of cosine over vectors) and a new `traversal-compare file-consistency <elo-run-id>` command mirroring `embed-consistency`'s validation flow exactly: re-reads an existing `elo` run's per-step transcript snapshots (`transcripts/<variant>-step<N>.jsonl`, already saved on disk by every run), derives each repeat's touched-file set via `metrics.compute_metrics` (reused as-is, not reimplemented — a single-transcript list scopes it to one step instead of a whole continuum), and Spearman-correlates the resulting ranking against that same run's real LLM-judge consistency Elo ranking. Also extracted `spearman_rank_correlation` out of `embeddings.py` into a new small `stats.py`, now that it has two real, non-embedding-specific consumers.

Worked correctly on the first real run — no bugs this time, unlike `gte-large-en-v1.5`'s RoPE crash or `_answers_by_variant`'s JSON key mismatch. 30 new tests (`test_file_consistency.py` + `test_stats.py`), 155/155 total suite passes.

**Real result, run against all three stored `elo` runs (9 step-observations)**: mean Spearman rho = **+0.39**, 7 of 9 steps positive, only 2 negative. A real, moderate, mostly-consistent positive correlation between file-touch consistency and the LLM judge's answer-consistency verdict — a genuinely different outcome than embedding-based consistency's -0.17 mean, and one that actually supports the hypothesis it set out to test, on a sample the same size. Not proof at n=9, but a real, free signal worth keeping around rather than a validated-and-shelved experiment.

Not decided yet whether this should become a real headline metric alongside (or ahead of) `run_consistency_elo`, but unlike the embeddings result, this one doesn't argue against itself — worth a deliberate follow-up session on whether/how to promote it, rather than deciding that in the same breath as building it.
