## Purpose

A running diary of the thinking behind toprope: fundamental ideas as they're first articulated, decisions made and why, plans drafted and revised. This is a record of *reasoning over time*, distinct from the rest of the harness (which records stable, current-state knowledge). When a diary entry's conclusion becomes settled fact, promote it into a proper reference or skill — the diary stays the historical trail, not the source of truth.

## Conventions

- One file per entry: `YYYY-MM-DD-HHMM-slug.md`, timestamp in the author's local time.
- Each entry starts with frontmatter:
  ```
  ---
  description: One-line summary of the entry's content, for disclosure listings.
  date: YYYY-MM-DD HH:MM TZ
  git:
    toprope-agentdev: <short-hash>   # this meta-repo, always included
    toprope: <short-hash>            # submodule, include if the entry concerns its source
    toprope-cli: <short-hash>        # submodule, include if the entry concerns its source
  ---
  ```
  Record the commit each relevant repo was actually at while writing the entry (`git rev-parse --short HEAD` in the repo; `git submodule status` from the meta-repo root for the submodules), not the commit the entry's own changes land in — the diary records what state was being worked on, and an entry is written before its own commit exists. Only list submodules the entry actually discusses; always include the meta-repo itself. If a repo has uncommitted changes at the time of writing, note that explicitly (e.g. `2759c54 (dirty)`).
- Entries are append-only history — don't edit past entries to reflect new thinking; write a new entry that supersedes or amends the old one, and note what it supersedes.
- Keep entries focused: one idea, decision, or planning pass per entry. Split unrelated thoughts into separate files even if written the same day.

- `2026-08-21-0848-comparison-selection-made-adaptive-not-fixed-schedule.md` — User caught a real gap: comparison selection used a fixed schedule (round-robin, or a uniform-random subset) decided before any rating existed, which misses the actual reason Elo beats a fixed rubric — ratings propagate transitively, so a well-targeted sparse set of comparisons can rank a pool without comparing every pair. Replaced with adaptive selection (`_next_pair`): same total budget, but each next comparison is chosen after the prior one's rating update, prioritizing uncompared pairs weighted toward the least-played competitors (so a limited budget can't starve one competitor the way random sampling could), tie-broken toward closest-in-rating pairs. 7 new/rewritten tests target exactly the two properties this was about (no starved competitor, no repeated pair within budget); not re-verified live, on the judgment that a targeted algorithmic fix already covered by unit tests didn't need another real judge-call budget spent to re-confirm it.
- `2026-08-21-0855-sort-mst-replaces-the-ad-hoc-adaptive-pairing.md` — Asked to read Nagle et al., "Optimal Pairwise Comparison Procedures for Subjective Evaluation" (arXiv:2508.17840), and choose a pairing algorithm from it. Its winner, **Sort-MST** (each round = a minimum spanning tree over competitors weighted by current rating difference — prefers close-rated pairs, Kruskal's tree structure guarantees full per-round coverage for free), replaced the entry above's ad-hoc least-played/closest-rating heuristic — better grounded (closest-rating is now the primary signal, matching the real Bradley-Terry information-maximization argument, not a tiebreaker) and simpler (no separate games-played bookkeeping). Real behavior change: the comparison budget is no longer capped at full round-robin, since the paper explicitly tests up to 15x that and finds accuracy still improving. 22 tests, 120/120 suite passes; not re-verified with a fresh live run, same reasoning as the entry above.
